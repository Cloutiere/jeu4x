## M1 — Le Palais révisé (R-113 rév.)

- **Choix de forme de données** (l'agent tranche, veto possible) : champ dédié **`culturePerCitizenCap: { perCitizen: 1, cap: 5 }`** sur `palais` dans `buildings.json` — le champ flat `culturePerTurn` est SUPPRIMÉ (données, type `BuildingData` et libellé `effect` mis à jour). Raison : surcharger `culturePerCitizen` (l'option « culturePerCitizen + culturePerCitizenCap » du handoff) aurait noyé le Palais dans la lignée Temple/Cathédrale — celle-là même que Stonehenge multiplie et que le Communisme annule. Le champ dédié tombe dans la part « Palais » (flat) du moteur : **×2 Monarchie s'applique, Stonehenge et Communisme ne l'affectent pas**, sans aucun cas particulier. Calibrage = éditer le JSON (les deux valeurs sont indépendantes).
- `cultureGains` (`culture.ts`) : part Palais = `perCitizen × min(pop, cap)` ; tests verrouillés (`expansion-culturelle.test.ts` + révisions `culture/phase7h/phase7k/data`) : pop 1→1, 2→2, 5→5, 6→5, 20→5 ; Monarchie ×2 sur la part Palais SEULE ; Communisme annule Temples/Cathédrales mais pas le Palais ; Stonehenge multiplie la part Temples mais pas le Palais ; Magna Carta (Tribunal +1/citoyen) et Théâtre (×2 total) inchangés ; Temple/Cathédrale NON plafonnés (20 pop × Cathédrale = 40).
- **UI cohérente** (critère d'acceptation) : `CityPanel.svelte` passait `cultureGains` SANS les effets de régime — le panneau de ville n'aurait pas reflété le ×2 Monarchie ni l'annulation Communisme. Il passe désormais `effectsFor(player)` (source unique, miroir `turn.ts`) ; la jauge affiche le rendement révisé (vérifié en e2e : « 10 / 150 — 2 culture/tour » à pop 2).
- **⚠ Consigne pacing GP post-calibrage (M1.3 — pour décision Erik, RIEN touché)** : la révision accélère le canal culture/GP. Capitale pop 2 : **2 culture/tour (au lieu de 1)** → 1er GP (seuil 150) en **75 tours de Palais seul** (contre 150). Avec un Temple en pop 4 : 8/tour → ~19 tours. La montée en pop amplifie l'effet (Palais plafonné à 5 mais Temples scalaires). Les seuils `greatPersonCultureThresholds` (T-27) sont **inchangés** et éditables dans `culture.json` si Erik juge le rythme trop rapide — contrôle séparé, hors périmètre.

## M2 — Culture cumulée + rayon culturel

- **`city.cultureCumulee`** (état + `fixtures.ts` + les 3 créations de ville moteur) : additionne **exactement les mêmes gains** que `cultureStored` chaque tour (y compris le ×1,5 Settle Artiste/Penseur), **jamais consommé** — le canal GP soustrait `cultureStored` seul ; test « les deux ne se volent rien » : à stored 149 (+4/tour), le GP spawn et laisse stored 3, cumul 4. **Anarchie (R-122)** : traitement identique à `cultureStored` — l'accumulation S'ARRÊTE (gains à zéro, compteur figé, pas remis à zéro), verrouillé par test.

Données `culture.json` : `cultureExpansionThresholds: [10, 100, 1000, 10000]`, `cultureExpansionMaxRings: 5` — le plafond n'est **lié que si la table dépasse 5** (testé avec une table étendue ; avec les données par défaut le max est 4 anneaux). Aucune lecture d'état, entrée négative → 0.
- **Zéro consommateur gameplay** : `rayonCulturelDe` n'est appelée QUE par le rendu (M3). Garde-fou testé : `workRadiusOf`/`tileWorkable` lisent les bâtiments, jamais la culture — les tuiles travaillables, les worked tiles et le rayon du Tribunal sont intouchés. Pas de pression/conversion/flip.
